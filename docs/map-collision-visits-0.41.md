# 0.41 原版地图阻挡与物件访问

截图中的山体横跨三列、两行，旧版仅阻挡锚点一格。原始 OBJECTS.TXT 为此山体定义了四个阻挡格。本版将 1305 个已验证对象模板编译进规则核心，寻路与实际移动使用同一份阻挡掩码，并与地图绘制共享对象名称和入口偏移；矿山、水车、城堡的主体也不能穿过。斜走仍检查两侧格子，不允许从两个障碍的夹角穿过。部分足迹已探索时也绘制对应山体，随后由迷雾覆盖未探索部分。

练习图生成时按完整足迹清理道路、入口和物件周围障碍，避免随机山体盖住原先只清理了一格的道路。旧档读取不会写回原文件；若旧版英雄脚下落入非法山体格，则清理覆盖脚下的装饰；若身处建筑主体内，则放回最近的已探索可通行格。资源、部队、经验和日期保留。

## 本轮核对及修正

| 物件 | 本版行为 | 动画 |
|---|---|---|
| 魔法井 | 不足上限时补满；同一英雄每天只能使用一口井一次；满魔不消耗次数 | 原始 1 帧，保持静态 |
| 风车 | 每座每周领取一次，3–6 个非木材、非金币资源；新周恢复 | 原始 8 帧，领完仍转动 |
| 水车 | 每座每周一次；第一周 500 金币，之后每周 1000 | 原始 8 帧，领完仍转动 |
| 一级魔法神殿 | 需要魔法书，传授配置的一级法术；不发 600 经验，已学会时不重复奖励 | 原始 8 帧 |
| 方尖碑 | 首次拜访计入拼图，重复不增加进度；打开藏宝图，不直接揭开冒险迷雾 | 原始 1 帧 |
| 矿山 | 主体阻挡，入口可达，占领后的每日产出继续按原规则结算 | 使用对应原始 DEF；部分静态，金矿等多帧 |
| 木材、矿石、金币等 | 到达才领取并移除，隔空访问无效 | 按各自原始帧数，不为静态资源添加闪动 |

水井、风车、水车、神殿访问显示确认窗；打开期间暂停行军，确认后返回地图。受野兵守卫的物件先战斗，胜利后结算效果并在战报后显示确认窗。悬停说明显示已领取、已拜访、当日是否已饮用井水。

藏宝图支持方尖碑进度、原版城堡拼图覆盖素材和实际地图的棕色地形图。P 打开藏宝图，D 在英雄所在格挖掘。挖掘需要当天尚未移动，会耗尽行动力；埋藏点只产出一件圣杯。当前各阵营暂用已核对坐标的城堡覆盖画，九城各自拼图布局与完整圣杯建筑效果尚未接入。

## 尚未完全一致

宝箱当前仍直接给配置的金币，尚无原版金币/经验二选一；神器仍采用练习图的简化装备效果。多英雄分别拜访、完整所有地图对象、圣杯城镇建筑和所有原版提示文字仍未完成。地图动画使用原始帧与固定时钟，180 ms/帧是当前客户端设置，尚未以未修改原版程序逐项校准播放速度。

## 来源与验证

- 原版演示包中的 OBJECTS.TXT 和 DEF；模板保存在 `assets/demo/adventure.json`，由 `scripts/generate-adventure-geometry.py` 编译，规则测试逐条对照源数据。
- 1999 年原版手册第 20 页：方尖碑、藏宝图与整日挖掘。
- VCMI 官方项目 `config/objects/magicWell.json` 的每日效果条件和 `config/factions/castle.json` 的原始拼图坐标；引用数据不引入其引擎代码，来源记录在 `references/object-review-0.41/source.json`。

普通、ASan/UBSan 和 Mac 通用发布构建均通过 321 项规则、14 项资源格式、8 项 H3M 格式及 22 项音频检查。三种构建各完成 417 张场景截图及 21 份流程审计，PNG 哈希和审计内容全部一致。

另对访问后五种物件的实际截图像素取样：井和方尖碑保持静态，风车、水车、神殿随时间变化。取样排除了附近英雄旗帜，避免把旗帜变化误判为物件动画；三种构建的取样结果一致。

完整练习图从新游戏正常建设、招募、探索、施法，游戏内第 19 天通关：72 次移动、4 场战斗、4 次魔法神箭、1 次升级选择、1550 经验。本轮未做真人鼠标全程通关，所有自动流程使用隔离临时存档目录。

最终规则、交互、整图自动通关与安装包记录见 `data/native/validation-0.41.json`，截图与哈希见 `references/validation/0.41/`。通用包包含 arm64/x86_64，最低 macOS 14，应用签名和 DMG 校验通过；尚未经过 Developer ID 签名或 Apple 公证。
