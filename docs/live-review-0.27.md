# 0.27 实机通关与界面修复

用户解锁 Mac 后，在 0.26.0 原生应用中从新游戏开始，以实际鼠标完成固定 36×28 边境练习地图。此后 0.27.0 仅修复下述提示条/按钮遮挡，并运行完整自动流程与修复后的实机界面补验。0.26 历史归档保持原样，不能把当时的锁屏状态当成本次状态。

## 真实游戏流程

通过菜单新建城堡地图，拾取起点宝箱（金币 10000→11500），回城建一级行会、花 500 金币购书，逐日建高级射手塔和高级岗楼；通过部队界面付费升级枪兵/弓箭手，招募并等待正常周增长。第 15 天部队为 70 戟兵、43 神射手、4 狮鹫，金币 12580，没有注入资源、兵数、HP、法术、迷雾或位置。

沿途占领伐木场、拾取矿石，贸易站中断行军后退出并继续路线，访问魔法泉、拾取金币和骑士之剑（攻击 2→4），再经过骷髅巡逻队、智慧神殿、金矿、恶狼群、水晶矿、半兽人哨兵、东北宝箱，最终攻下黑鸦堡。

实际点选魔法书、目标并施法：骷髅战的魔法神箭使魔法值 20→15、敌方 HP 180→160；恶狼战对狮鹫施放护体神盾，魔法值 17→12、对应效果激活；半兽人战及最终城镇战各再用一次神箭。另验证神箭指向友军不会扣费，右键可取消选中的法术。普通攻击验证神射手两次射击；后续通过战斗工具栏启用现有自动战斗，播放真实行动和伤亡，没有修改结果。

第 18 天地图胜利，英雄 3 级、2150 经验、金币 22280，剩余 60 戟兵与 43 神射手，魔法值 2。四场战斗均完成结算，两次技能选择确认后回到主菜单，状态中 battle/report 均为空、待选技能为空、黑鸦堡所有者为玩家。截图、逐步检查点和原生输入追踪见 [实机截图索引](../references/validation/0.27/live-evidence.html)。自动流程采用不同的普通战斗决策，因此最终伤亡不同，不将其与实机结果混为一条记录。

## 全屏与输入

真实 MacBook 全屏窗口为 1512×949 点、输出 3024×1898 像素，Retina 比例为 2。地图视口扩大，地块保持 32 点、右栏保持 192 点。窗口缩小到 1001×743 点时输出 2002×1486，F4 往返可用；小地图拖动和地图拖动后的释放坐标可用。

自动操作工具有时无法定位切换后的全屏窗口进行坐标点击，返回 noWindowsAvailable；截图和 F4 仍可用，游戏状态保持。已在全屏验证起点探索与拾取，在窗口模式完成后续整张地图，不能称为“全程全屏鼠标通关”。0.27 另成功在全屏选择 6,17 路线、点击移动英雄并拾取 8 木材（木材 15→23），随后读取原生输入追踪确认实际窗口/输出尺寸；再次切换到全屏战斗后，工具仍偶发相同定位错误。字母快捷键在该自动操作工具中未成功触发，没有将其记为通过，也没有据此判定游戏键盘实现有缺陷。

## 修复与验证

- 行会购书/打开书按钮从 y=535 上移到 y=515，使其底边位于状态文字区域上方。
- 战斗使用自身状态栏显示提示，移除覆盖底部工具栏的第二个通用提示框；行会、战报和升级界面也移除重复覆盖框。
- 新增带活动提示的四种渲染局面，对比实际像素，检查战斗按钮、战报确认按钮、行会资源栏和升级页底部未被遮挡。正常购书与完整自动通关的点击位置同步更新。

原版逐屏检查仍覆盖全部 21 个当前 Scene，参考、版本差异和临时页面见 [0.26 对照表](fullscreen-review-0.26.md)及 [并排画面](../references/validation/0.26/interface-comparison.html)。本次是修复实机可见问题，未把临时升级整页、独立部队页或其他扩展页改称为原版一致。

本次没有开发存档兼容功能；隔离 JSON 文件仅用于保留测试证据和复现局面。战略敌方 AI、真正攻城、原版战役、H3M、多英雄、完整装备与全部法术等仍未完成。

## 本次补验结果与归档

0.27 使用本轮真实形成的检查点，在隔离目录复现行会与战斗，无修改资源或战斗属性：行会卷轴提示、上移后的打开书按钮均可用；全屏行军拾取正常；带活动提示的战斗工具栏全部可见，启用自动战斗后正常出现战报，确认后可返回地图并新建重置。最后关闭隔离窗口，以默认目录和 --fullscreen 启动新版，停在主菜单供用户开始游戏。

Mac 构建现在对整个 .app 作本地临时签名，绑定 Info.plist 与图标，两种构建均通过 codesign --verify --strict 校验。受限命令环境中的 open 另出现过 kLSNoExecutableErr；使用已获准的 GUI 启动权限后正常启动，因此不把该错误全部归因于应用签名。

普通与 ASan/UBSan 均通过 284 核心检查、14 资源格式检查、22 音频检查和 270 张界面回归。全部 270 PNG 与六份审计文件逐字节相同。测试使用 SDL dummy 驱动；实机 JPEG 来自原生窗口截图，单独归档，未转换为离屏 PNG。签名步骤只改变包签名，游戏代码与上述渲染检查一致，随后已实机启动复核。
